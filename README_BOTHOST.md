# Creator Discord Bot — Bothost

## Параметры запуска
- Python: 3.11 или 3.12
- Главный файл: `bot.py`
- Команда запуска (если требуется): `python -u bot.py`
- Зависимости: `requirements.txt`

## Установка
1. Останови контейнер.
2. Сохрани папку `data` со старой базы, если она уже есть.
3. Загрузи и распакуй архив в корневую папку проекта.
4. Убедись, что `bot.py` и `requirements.txt` лежат прямо в корне.
5. В переменных окружения добавь `BOT_TOKEN` со свежим токеном Discord.
6. Запусти `bot.py`.

Код сначала проверяет `BOT_TOKEN`, затем `DISCORD_TOKEN`, затем `TOKEN`.
Настоящий токен не добавляй в архив и не отправляй никому.

## Discord Developer Portal
В приложении бота → Bot включи:
- Server Members Intent
- Message Content Intent

Приглашай бота со scopes `bot` и `applications.commands`.
Нужны права: View Channels, Send Messages, Read Message History, Embed Links,
Attach Files, Manage Roles, Manage Channels, Manage Messages, Moderate Members,
Kick Members, Ban Members, Move Members, Connect, Manage Events.

Роль бота должна находиться выше ролей, которыми он управляет.

## Заявки на роли
Команда `/role_requests` открывает панель настройки.
- «Настроить каналы» — ID канала панели, ID категории приватных заявок, ID роли проверяющих.
- «Настроить роли» — ID ролей «Новичок», «Зритель» и необязательной роли «На проверке».
- «Опубликовать панель» — публикует кнопки для участников.

После отправки формы бот сразу подтверждает взаимодействие, загружает список ролей сервера,
проверяет ID и сохраняет настройки. Если ID неверный, он сообщит, какая роль не найдена.
Если возникает внутренняя ошибка, подробности будут записаны в консоль Bothost.

Для постоянного хранения настроек сохрани папку `data` и настрой постоянное хранилище хостинга.


## Исправление форм настройки ролей и каналов
В этой версии обработчики обеих форм отвечают Discord немедленно, до любых сетевых запросов.
Роли берутся из уже загруженного кеша сервера; дополнительный `fetch_roles()` не вызывается.
Если ID неверный, бот отправит понятное приватное сообщение. Если случится исключение Python,
оно будет записано в лог Bothost.

При обновлении останови контейнер, замени `bot.py` и остальные файлы из архива,
не удаляй `data/bot.sqlite3`, затем запусти бота заново.


## Обновлённое оформление приветствия
Команда `/welcome` → «Тест» показывает обновлённую карточку приветствия:
- фиолетовый фирменный акцент TomsyYouTube;
- заголовок и автор с иконкой сервера;
- аватар нового участника;
- блоки профиля, количества участников и платформ;
- подсказки «С чего начать»;
- кнопки «Читать правила» и «Получить роли»;
- баннер сервера в карточке, если он установлен.


## Уведомления YouTube и Twitch
- Введи `/youtube` → «Добавить канал»: укажи ID канала Discord для уведомлений и YouTube Channel ID, начинающийся с `UC`.
- Введи `/twitch` → «Добавить канал»: укажи ID канала Discord и логин Twitch.
- YouTube проверяется каждые 3 минуты через публичный Atom feed.
- Twitch проверяется каждую минуту. Для этого добавь в переменные Bothost `TWITCH_CLIENT_ID` и `TWITCH_CLIENT_SECRET` из Twitch Developer Console.
- Первое обнаружение YouTube-ролика сохраняет текущую запись как стартовую; уведомления отправляются о следующих новых роликах. Если Twitch-канал уже в эфире при первом опросе, бот может отправить уведомление об активном эфире.

## Автомодерация `/automod`
Панель позволяет включать/выключать:
- антиспам;
- фильтр сторонних ссылок;
- фильтр рекламы казино и ставок.

Кнопка «Настроить наказания» позволяет настроить порог сообщений, интервал и длительность трёх тайм-аутов. По умолчанию: 6 сообщений за 8 секунд; первое нарушение — 5 минут, второе — 10 минут, третье — 30 минут; четвёртое нарушение — кик. История нарушений хранится в SQLite и сбрасывается после 30 дней без новых нарушений.

Кнопка «Разрешённые сайты» задаёт белый список доменов. По умолчанию разрешены `youtube.com`, `youtu.be`, `twitch.tv`, `discord.com`, `discord.gg`. Если фильтр сторонних ссылок включён, ссылка на домен вне списка приводит к удалению сообщения и исключению участника. Фильтр казино отдельно распознаёт ключевые слова, названия казино и ставок и также исключает нарушителя.

При наказании бот отправляет участнику личное сообщение с причиной, если у него открыты личные сообщения. Для работы нужны права `Manage Messages`, `Moderate Members`, `Kick Members` и `View Channels`; роль бота должна быть выше ролей участников, которых он модерирует.


## Обновлённая система поддержки / тикетов
В канале обращения отображаются две кнопки:
- `✅ Помогли` — закрывает обращение с результатом «Проблема решена — поддержка помогла».
- `🔒 Закрыть обращение` — закрывает обращение без отметки о решении.

При закрытии бот:
1. Собирает историю сообщений канала, включая авторов, время и ссылки на вложения.
2. Отправляет автору обращения красивую карточку и историю непосредственно в личные сообщения Discord — без TXT и без файлов.
3. Отправляет сотруднику, который закрыл обращение, отдельную копию истории в личные сообщения.
4. Записывает результат закрытия и сотрудника в журнал.
5. Удаляет канал обращения после успешной доставки истории автору.

Если у автора закрыты личные сообщения, бот не удаляет канал, чтобы не потерять переписку. Попроси автора разрешить личные сообщения от участников сервера и повтори закрытие.

Для работы требуются права бота:
- Manage Channels
- View Channels
- Send Messages
- Read Message History
- Embed Links

Миграция SQLite добавляет к таблице `tickets` поля `closed_by`, `close_reason`, `closed_at` без удаления старых записей. Не удаляй `data/bot.sqlite3` при обновлении.

## Изменение доставки истории тикета
История обращения отправляется прямо в личные сообщения Discord:
- отдельная красивая карточка с результатом и тем, кто закрыл обращение;
- сообщения истории разделены на страницы-embed;
- в каждой записи указаны автор, дата и время, текст и ссылки на вложения;
- каждая страница отправляется отдельным Discord-сообщением, чтобы не превышать лимиты Discord;
- после успешной отправки истории автору бот удаляет канал обращения.


## Визуальное оформление и производительность
- Единый бренд TomsyYouTube: Twitch-purple + YouTube-red, автор карточки с аватаром бота, фирменные подписи и отдельные блоки.
- Панель поддержки оформлена как официальный creator support center; карточка обращения показывает автора и команду.
- Личная история обращения приходит embed-страницами прямо в Discord, без TXT и других файлов.
- SQLite работает в WAL-режиме с NORMAL synchronous и busy timeout.
- Часто используемые настройки сервера кэшируются в памяти.
- Счётчик сообщений копится в памяти и сохраняется одной пакетной операцией раз в 15 секунд, а не отдельной записью на каждое сообщение.
- Опыт и монеты пересчитываются не чаще одного раза в минуту на участника.
- YouTube и Twitch используют одну повторно используемую aiohttp-сессию с ограничением соединений и DNS-кэшем.
- Проверки YouTube/Twitch выполняются параллельно с лимитом 5 запросов, чтобы не задерживать цикл при большом количестве каналов.
- При остановке бота накопленная статистика сохраняется, HTTP-сессия корректно закрывается.

Это уменьшает лишние операции и сетевые задержки. Фактическая плавность также зависит от CPU/RAM тарифа хостинга, качества сети и количества серверов/подписок.


## Исправление Discord Unknown interaction (10062)
Кнопка создания обращения сразу подтверждает взаимодействие через `defer(ephemeral=True, thinking=True)`, до создания канала. Финальное сообщение отправляется через followup, поэтому обычная задержка Discord при создании канала не приводит к истечению первоначального 3-секундного окна. Ошибки отсутствия прав и HTTP-ошибки создания канала обрабатываются отдельно.


## Исправление Discord Unknown interaction (10062)
- Кнопка создания обращения подтверждает interaction через `defer()` сразу, до запросов к БД, создания канала и отправки логов.
- Кнопка закрытия обращения также подтверждает interaction до чтения истории и отправки DM.
- Итоговые ответы отправляются через `interaction.followup.send()` (общая функция `say()` автоматически выбирает followup после defer).
- При обновлении останови предыдущий процесс и запусти только один экземпляр бота с этим токеном.


## Система правил — обновление
- Количество правил не ограничено искусственным лимитом в 25 записей.
- Правила публикуются в одном красивом Embed-сообщении с кнопками «Назад» и «Вперёд».
- На каждой странице показывается одно правило целиком; длинные старые записи автоматически разбиваются на продолжения.
- Текст правила в форме можно вводить длиной до 3500 символов; текст не обрезается при публикации.
- Добавление, изменение и удаление правила автоматически обновляет опубликованный список, если канал уже настроен.
- Административный список правил также разбит на страницы по 8 записей.
- Кнопки публичной навигации зарегистрированы как persistent view и продолжают работать после перезапуска бота.
- Существующая таблица `rules`, настройки и база `data/bot.sqlite3` сохраняются; миграция не удаляет пользовательские данные.

Настройка: команда `/rules` → «Канал» → укажи ID текстового канала → добавляй правила. После этого публикация обновляется автоматически. Кнопка «Опубликовать» остаётся для ручного обновления.
